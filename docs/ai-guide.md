# AI 사용 가이드 (바이브코딩 포함)

목표는 코드를 많이 만드는 것이 아니라 **AI 가 쓴 코드를 판단하고 검증하는 능력**을 기르는 것입니다. 그래서 단원 안에서 구간별로 AI 사용법을 나눕니다.

## 구간별 규칙

| 구간 | AI 에게 시켜도 되는 것 | 먼저 내가 해야 하는 것 |
|---|---|---|
| **개념 읽기** | 어려운 용어 풀이, 다른 비유 요청 | 문서를 먼저 읽고, 어디가 막혔는지 **정확히** 말하기 |
| **직접 구현 (TODO)** | 개념 설명, 의사코드 검토, 내가 쓴 코드 리뷰, 오류 메시지 해석 | **먼저 내 힘으로 15분** 시도. 전체 코드 생성 요청은 마지막 수단 |
| **오류 실험** | 읽기 어려운 부분 설명 | 어디가 이상한지 먼저 적고, 몇 개 실패할지 예측 |
| **응용** | 개념 질문 | 해결 코드 작성은 내가 |
| **설정·반복 코드** (패키지 설치, 출력 포맷 등) | 자유롭게 | — |
| **자기 말로 설명** | 쓴 글에 대한 **피드백** (정답 아님) | 초안은 내가 쓰기 |

## AI 코드를 받았을 때 점검표 (바이브코딩 검증)

AI 가 코드를 줬다면 **붙여 넣기 전에** 아래를 확인하세요.

1. 이 코드가 **모델(또는 함수)에 무엇을 보내는지** 말할 수 있는가? (입력)
2. 돌려주는 것과 **어디에 저장하는지** 말할 수 있는가? (출력·상태)
3. 입력 배열/객체를 **몰래 바꾸지 않는가**? (`push`, 전역 변수)
4. 첫 번째 호출만이 아니라 **두 번째·세 번째 호출**에서도 맞는가?
5. 오류가 나면 어디서 멈추는가?
6. 이 단원의 검사(`npm run check`)를 통과하는가? 통과해도 4번을 직접 따져 보았는가?

연습은 각 단원의 "오류 실험"에서 합니다.

## 막혔을 때 (회복 경로)

1. 15분 시도 → `npm run hint -- u01 1` (개념)
2. 여전히 막힘 → `npm run hint -- u01 2` (의사코드)
3. 여전히 막힘 → `npm run hint -- u01 3` (부분 코드)
4. 15분 더 막힘 → `npm run solution -- u01` (정답과 해설)
5. **정답을 닫고** 내 코드를 처음부터 다시 쓴다. 그 다음 `npm run check`

정답을 봤다는 이유로 진행이 막히거나 감점되지 않습니다. 단 `npm run status` 에 "정답 열람 N번" 이 기록돼, 나중에 어느 단원이 어려웠는지 돌아보는 자료가 됩니다.
