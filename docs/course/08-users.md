# 8. 두 사용자의 대화 분리하기

**문제집 8/8 · 풀이 파일: practice/08-users.ts**

## 1. 지금 무엇을 만드나요?

앞에서 만든 대화 함수를 재사용합니다. alice와 bob의 기록을 나눠 서로의 대화를 보지 못하게 합니다.

**직접 바꿀 코드:** practice/08-users.ts의 작성 구역. 이미 작성한 내용은 자동으로 초기화하지 않습니다.

**입력은 누가 넣나요?** say(userId, question)에 사용자 ID와 질문을 번갈아 넣습니다.. :check가 함수를 호출하면서 넣어 주므로 사용자가 함수 틀이나 호출 코드를 다시 작성할 필요는 없습니다.

## 2. 해결할 문제와 목표

alice와 bob이 번갈아 질문합니다. 사용자 ID별로 기록을 저장하는 서비스를 만드세요. newConversation과 ask는 앞 단계에서 작성한 함수를 가져왔습니다. 서비스마다 보관함도 독립적이어야 합니다.

alice: 4명 방 추천 → 목록. bob: 그중 싼 곳? → 대화에서 찾을 수 없음. alice: 그중 싼 곳? → R-102. 새 서비스도 이전 대화를 몰라야 함.

검사는 제시된 예뿐 아니라 다른 입력도 넣습니다. 예시 답을 문자열로 고정해서 반환하면 통과하지 못합니다.

## 3. 실행해서 차이부터 확인하기

터미널의 단계가 **8/8**인지 확인하고 :check를 입력하세요. 문법·타입 검사 후 함수가 실행됩니다. 시작 코드는 아직 목표 동작을 하지 않으므로 실패하는 것이 정상입니다. 이미 작성한 코드가 통과하면 다음 실험까지 진행하세요.

출력에서 **입력 → 기대 → 실제 → 판정 → 고칠 부분**을 읽으세요. 문법·타입 오류라면 실행 전 작성 구역의 줄 번호와 수정 이유가 나옵니다. 실행 검사에서 실패한 지점 뒤의 검사는 수정 후 다시 수행합니다.

## 4. 이번 문제에 필요한 설명

Map은 사용자 ID로 값을 넣고 꺼내는 저장소입니다. `const prices = new Map<string, number>(); prices.set("apple", 100); prices.get("apple");`의 결과는 100, 없는 키는 undefined입니다. 이번 값은 숫자가 아니라 Message[]입니다. 사용자별 Map은 createChatService 안, say 밖에 두어야 같은 서비스의 다음 호출에도 유지됩니다.

## 5. 어떤 부분을 어떻게 고치나요?

1. createChatService 안, return 앞에 Map<string, Message[]>를 만듭니다. say가 호출될 때마다 새로 만들지 않습니다.
2. say 안에서 userId로 기록을 조회하고, 없으면 newConversation()으로 시작합니다.
3. ask(그기록, question)을 await로 호출합니다.
4. 결과의 messages를 같은 userId에 set으로 저장하고 answer를 반환합니다.

**자동 제공되는 함수 틀(입력하지 않음):** `export function createChatService(): { say(userId: string, question: string): Promise<string> }`. 이 틀 안의 작성 구역만 편집합니다. 아래가 새 파일의 작성 구역 시작 상태입니다. 이미 작성했다면 :show에 나온 현재 줄을 기준으로 수정하세요.

```ts
  return {
    async say(userId, question) {
      return "아직 사용자 기록을 저장하지 않음";
    }
  };
```

:edit으로 기존 코드를 엽니다. 한 줄을 바꾸려면 :set 줄번호 코드, 줄을 넣으려면 :insert 줄번호 코드, 삭제는 :delete 줄번호입니다. 전체를 다시 작성하려면 :paste → 함수 안 코드 여러 줄 → :done을 사용하세요. 마지막에 :save를 입력합니다.

저장하기 전에는 :list로 줄 번호와 내용을 확인하고, 잘못 고쳤다면 :undo로 마지막 편집을 되돌릴 수 있습니다. :cancel은 이번 편집 전체를 취소합니다. 번호와 │ 표시는 코드에 입력하지 않습니다.

## 6. 저장·검사 결과를 확인하기

:save를 입력하면 문법·타입 검사 → 저장된 코드 표시 → 자동 실행 검사가 이어집니다. 문법·타입이 틀리면 기존 파일을 바꾸지 않고 편집 상태로 남습니다. 출력된 줄을 :set으로 고치고 다시 :save하세요.

정상 저장 뒤에도 동작이 다르면 **수정 필요**가 표시됩니다. 실제 값이 기대와 어떻게 다른지 확인하고 :edit로 다시 고칩니다. :check는 저장한 코드를 언제든 다시 검사합니다.

성공하면 현재 단계의 입력별 결과가 모두 일치하고 **통과**가 표시됩니다. 이전 단계까지의 전체 재검사는 :next에서 수행합니다.

막히면 이 챕터 안에서 해결할 힌트: 함수 안에 Map<string, Message[]>를 만들고, { async say(userId, question) { ... } }를 반환하세요. get으로 조회하고 없으면 새 대화. ask 뒤 set으로 갱신하고 answer 반환. Map은 say 밖에 둡니다.

## 7. 다른 입력으로 직접 실행하기

```text
:try 그중 가장 저렴한 곳은?
```

먼저 기본 4명 방 추천을 자동 실행한 뒤, 방금 넣은 글을 후속 질문으로 실행합니다. 8번에서는 alice의 후속 질문입니다. :try는 결과를 관찰하는 실험이고 통과 판정은 :check가 담당합니다. 별도 필기는 없습니다.

## 8. 다음 단계로 이동

검사가 통과하면 :next를 입력합니다. 현재와 이전 코드들을 재검사한 뒤 다음 단계로 이동합니다. 이전 단계가 실패하면 해당 번호까지 :back으로 돌아가 수정하세요. 터미널에 다음 단계가 표시되면 아래 링크를 누릅니다. 마지막 실습에서는 “모든 실습을 통과했습니다”가 표시됩니다.
