# 5. 서로 독립적인 새 대화 만들기

**문제집 5/8 · 풀이 파일: practice/05-start.ts**

## 1. 지금 무엇을 만드나요?

이어지는 대화를 만들기 전에 출발 상태를 준비합니다. 사람마다 별개 대화를 만들 수 있어야 합니다.

**직접 바꿀 코드:** practice/05-start.ts의 작성 구역. 이미 작성한 내용은 자동으로 초기화하지 않습니다.

**입력은 누가 넣나요?** 입력 인자 없음. newConversation()을 두 번 호출해 서로 영향을 주는지 검사합니다.. :check가 함수를 호출하면서 넣어 주므로 사용자가 함수 틀이나 호출 코드를 다시 작성할 필요는 없습니다.

## 2. 해결할 문제와 목표

system 안내문 하나만 있는 새 메시지 배열을 만드세요. 매번 호출할 때 별개의 배열이어야 합니다.

newConversation() → [system]. 두 번 호출한 배열은 서로 다름. 한쪽을 수정해도 다른 쪽은 그대로.

검사는 제시된 예뿐 아니라 다른 입력도 넣습니다. 예시 답을 문자열로 고정해서 반환하면 통과하지 못합니다.

## 3. 실행해서 차이부터 확인하기

터미널의 단계가 **5/8**인지 확인하고 :check를 입력하세요. 문법·타입 검사 후 함수가 실행됩니다. 시작 코드는 아직 목표 동작을 하지 않으므로 실패하는 것이 정상입니다. 이미 작성한 코드가 통과하면 다음 실험까지 진행하세요.

출력에서 **입력 → 기대 → 실제 → 판정 → 고칠 부분**을 읽으세요. 문법·타입 오류라면 실행 전 작성 구역의 줄 번호와 수정 이유가 나옵니다. 실행 검사에서 실패한 지점 뒤의 검사는 수정 후 다시 수행합니다.

## 4. 이번 문제에 필요한 설명

system은 새 대화를 시작할 때 한 번 넣습니다. 다음 질문에서도 같은 기록 전체를 보내므로 system이 다시 전달됩니다. 질문마다 system 메시지를 추가하는 것은 아닙니다. 배열을 함수 밖에 하나만 만들면 여러 대화가 같은 배열을 사용하게 됩니다.

## 5. 어떤 부분을 어떻게 고치나요?

1. 매번 함수 안에서 새 배열을 준비합니다.
2. role이 system이고 content가 buildSystemPrompt()인 메시지 하나를 넣습니다.
3. 배열을 반환합니다. user 질문은 이 함수가 아니라 다음 단계에서 붙입니다.

**자동 제공되는 함수 틀(입력하지 않음):** `export function newConversation(): Message[]`. 이 틀 안의 작성 구역만 편집합니다. 아래가 새 파일의 작성 구역 시작 상태입니다. 이미 작성했다면 :show에 나온 현재 줄을 기준으로 수정하세요.

```ts
  return [];
```

:edit으로 기존 코드를 엽니다. 한 줄을 바꾸려면 :set 줄번호 코드, 줄을 넣으려면 :insert 줄번호 코드, 삭제는 :delete 줄번호입니다. 전체를 다시 작성하려면 :paste → 함수 안 코드 여러 줄 → :done을 사용하세요. 마지막에 :save를 입력합니다.

저장하기 전에는 :list로 줄 번호와 내용을 확인하고, 잘못 고쳤다면 :undo로 마지막 편집을 되돌릴 수 있습니다. :cancel은 이번 편집 전체를 취소합니다. 번호와 │ 표시는 코드에 입력하지 않습니다.

## 6. 저장·검사 결과를 확인하기

:save를 입력하면 문법·타입 검사 → 저장된 코드 표시 → 자동 실행 검사가 이어집니다. 문법·타입이 틀리면 기존 파일을 바꾸지 않고 편집 상태로 남습니다. 출력된 줄을 :set으로 고치고 다시 :save하세요.

정상 저장 뒤에도 동작이 다르면 **수정 필요**가 표시됩니다. 실제 값이 기대와 어떻게 다른지 확인하고 :edit로 다시 고칩니다. :check는 저장한 코드를 언제든 다시 검사합니다.

성공하면 현재 단계의 입력별 결과가 모두 일치하고 **통과**가 표시됩니다. 이전 단계까지의 전체 재검사는 :next에서 수행합니다.

막히면 이 챕터 안에서 해결할 힌트: 함수 안에서 배열을 새로 만들고 반환하세요. 안내문 내용은 buildSystemPrompt()를 사용합니다.

## 7. 다른 입력으로 직접 실행하기

```text
:try
```

이 함수는 입력 인자가 없으므로 system 안내문 하나가 반환되는지 봅니다. :try는 결과를 관찰하는 실험이고 통과 판정은 :check가 담당합니다. 별도 필기는 없습니다.

## 8. 다음 단계로 이동

검사가 통과하면 :next를 입력합니다. 현재와 이전 코드들을 재검사한 뒤 다음 단계로 이동합니다. 이전 단계가 실패하면 해당 번호까지 :back으로 돌아가 수정하세요. 터미널에 다음 단계가 표시되면 아래 링크를 누릅니다. 마지막 실습에서는 “모든 실습을 통과했습니다”가 표시됩니다.
