# 미완료 항목과 검증 상태

숨기지 않고 적어 둡니다. 이번 작업 범위는 "기존 자료 분석 → 대응표 → 커리큘럼 → 템플릿 → 실행·검증·화면 기반 → 첫 단원 견본" 까지입니다.

## 아직 만들지 않은 것 (의도적)

- U02~U14 단원 본문, 검사, 힌트, 정답 (견본 검토 후 확장)
- 장비 대여 도우미(U14) 요구사항·합성 데이터·뼈대
- 누적 복습 체크포인트 (U04, U08, U12 직후)
- LangGraph 단원용 구조 그래프 자동 추출 (현재 구조 그래프는 단원이 `unit.ts` 에 직접 선언. LangGraph 도입 시 `graph.getGraph()` 로 대체)
- 실제 LLM 연결의 자동 검증 (키가 없어 코드만 있고 **실행해 보지 않았습니다**)
- 노드 안에서 일어나는 state 변경 전후의 자동 기록 (U05 이후, 현재는 `turn` 의 대화 기록만)

## 알려진 한계

- `npm run check -- u01` (응용 없이)을 다시 돌려도 **이전의 응용 검사 결과가 진도에 남습니다.** 코드를 고친 뒤에는 `--apply` 로 다시 확인하세요. (검사 시각을 단원별로 따로 기록하는 개선이 필요)
- 학습 화면의 "▶ 새로 실행" 은 브라우저 `confirm()` 창을 씁니다. 자동 브라우저 테스트로는 누르지 못해, 같은 주소(`POST /api/rerun`)를 직접 호출해 동작만 확인했습니다.
- 학습 화면은 학습자 `work/` 를 읽기만 하지 않고 "새로 실행" 때 `check --apply` 를 실행합니다 (fake LLM 만 사용. 127.0.0.1 에서만 열림).
- 단원 수가 늘면 학습 화면의 구조 그래프 배치(단순 열 배치)가 복잡한 분기에 부족할 수 있습니다.

## 검증 상태

| 항목 | 상태 | 근거 |
|---|---|---|
| 타입 검사 (`npm run typecheck`) | 실행함 | 마지막 작업 보고에 결과 기재 |
| 정답 통과 · 미완성 실패 · 실험 실패 (`npm run selftest`) | 실행함 | 〃 |
| 구조 점검 (`npm run lint:units`) | 실행함 | 〃 |
| 학습 화면 (`npm run view`) 브라우저 확인 | 실행함 | 〃 |
| 사람이 푸는 데 걸리는 시간 | **미검증** | 추정치. FEEDBACK.md 로 측정 필요 |
| 설명의 이해 용이성 | **미검증** | 학습자 피드백 필요 |
| 예측 질문이 오개념을 잘 찌르는가 | **미검증** | 〃 |
| Windows 외 환경 | **미검증** | 이 PC(Windows 11, Node 26)에서만 실행 |
| LangGraph.js 버전 호환 | 설치만 확인 | U04 도입 때 import·실행 테스트 필요 |
