# 구조 점검 ≠ 교육적 품질

| | 무엇을 확인하나 | 어떻게 | 확인할 수 있는 것 | 확인할 수 없는 것 |
|---|---|---|---|---|
| **구조 점검** | 필수 파일 · 힌트 3단계 · 검사 · start/solutions 가 있는가 | `npm run lint:units` | 빠진 파일, 빈 문서 | 설명이 이해되는지 |
| **동작 점검** | 미완성은 교육용 오류로 실패, 정답은 통과, 틀린 실험 코드는 실패, 기록에 비밀값 없음 | `npm run selftest` | 검사가 의도대로 동작하는지 | 학습자가 이해하는지 |
| **교육적 품질** | 설명이 이해되는가, 시간이 맞는가, 예측이 도움이 되는가, 지루하지 않은가 | **사람이 풀어 보고 FEEDBACK.md 에 기록** | — | (자동으로는 불가능) |

## 교육적 품질을 검증하는 방법 (사람이 해야 함)

1. 학습자(또는 비슷한 수준의 사람)가 견본 단원을 푼다.
2. `FEEDBACK.md` 에 실제 시간 · 막힌 곳 · 부족한 설명 · 지루한 곳 · 힌트를 적는다.
3. 아래 기준으로 템플릿을 고친 뒤 다음 단원을 만든다.

| 신호 | 의미 | 조치 |
|---|---|---|
| 실제 시간이 목표의 1.5배 이상 | 단원이 너무 큼 | 분리하거나 설명을 줄임 |
| 힌트 3단계를 자주 봄 | 선수 지식이나 개념 설명 부족 | 02/03 문서 보강, 보충 단원 추가 |
| 정답을 봤는데도 다시 못 씀 | 이해 없이 따라 쓰기 | 예시 읽기·예측 단계 보강 |
| 예측이 늘 맞음 | 질문이 쉬움 | 오개념을 찌르는 질문으로 교체 |
| 예측이 늘 틀림 | 개념 설명이 모호 | 03 문서에 "없으면" 표 보강 |
| 검사 통과인데 설명은 못함 | 검사가 동작만 봄 | 회고 루브릭/응용 강화 |
